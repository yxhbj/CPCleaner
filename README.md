# CPCleaner

**Control Point Cleaner — Jaw 遮挡区 MLC 开口清理**

**静态 Step & Shoot 研究版 / Research only. Not clinically released.**

检查 Pinnacle 计划中被独立 Jaw 完全遮挡的 MLC 开口，经用户明确确认后，
仅修改符合已实现约束的目标叶片曲线，并自动读回核验。
独立运行，仅需 Pinnacle 脚本环境和 Python 标准库。

> 不用于患者治疗决策或临床交付。代码公开不代表机器兼容性、剂量等价性或临床批准。
> Trial 名不受前缀限制；每次进入都先弹出默认 **No** 的研究用途警告。
> 用户明确 Yes 后才继续检查；名称或确认都不是安全或研究隔离的充分条件。
> 仅在获得机构授权、具备备份和人工对账能力的研究环境中评估。

## 范围

- 仅支持光子静态 **Step & Shoot MLC**；不支持 VMAT、弧、动态 Jaw/角度。
- 不按型号白名单分支，读取每束机器的实际 MLC/Jaw 配置：
  X/Y 运动方向、独立/替代 Jaw、叶片数量/宽度/中心、内部坐标和闭合约束。
- 不把被 MLC 替代的 Jaw 当作独立实体遮挡；显示坐标取反不再次作用于原生数组。
- 保留有效区、边界/跨界开口和正常闭合间隙。
  `gap <= MinDynamicLeafGap + 0.0001 cm` 按原生闭合语义保留，
  同时保留可量化的静态最小间隙；比较使用十进制运算。
- 对候选优先参考**同一射束其他全部 CP 的同一叶对**：
  仅在它们全部已闭合、坐标精确一致且符合位置精度时采用该共同闭合坐标，
  保留参考坐标的合法闭合间隙，不取其他叶对或其他射束的坐标。
  从原开口到目标的整个移动范围（含叶端/舌槽及精度裕量）必须完全在独立 Jaw 遮挡下。
  因此完全遮挡的叶条带允许移到原开口以外；不能跨越有效照射区追求对齐。
- 无明确共同参考或移动范围不满足遮挡条件时，缩小至原开口内、靠近原中点的可量化静态最小间距。
  检查行程、最小间距、整体银行差、相邻叶和 carriage 约束。
  若某 CP 的对齐结果不满足约束，该 CP 本次所有对齐候选退回原中点规则，
  报告记录 `closureStrategy` 和约束回退原因；回退后仍冲突则整次拒绝清理。
  不移动相邻叶片补偿。**已经闭合的叶对保持原样，不作位置统一或追溯修复。**
- 固定 Jaw、附加 mMLC、无序/不连续叶条带及未知配置拒绝。
  已实现约束检查不等于穷尽所有机器可交付性要求。

## 构建

目标运行环境：Pinnacle 原生脚本和 Solaris 系统 Python **2.7** 标准库。
Python 2.7 已停止上游维护；本工具为既有隔离研究环境提供兼容，
不是部署过时 Python 到联网系统的建议。构建和合成测试也可使用 Python 3。

在源码目录执行；输出目录必须尚不存在：

```powershell
python -B .\build.py C:\Temp\CPCleaner /home/p3rtp/CPCleaner /usr/bin/python
python -B -m unittest discover -s .\tests -p test_jaw_mlc.py -v
```

Solaris 上也可本地构建：

```sh
/usr/bin/python -B build.py /home/p3rtp/CPCleaner /home/p3rtp/CPCleaner /usr/bin/python
```

后两个参数为**实际安装目录**和已有 Python 的绝对路径，不允许空格或 shell 元字符。
源码目录与输出目录必须不同；不要覆盖现有安装。
无需 pip、npm 或依赖下载。源码归档不是可直接执行的安装包：先按实际路径构建。

## 安装和独立启动

1. 将完整构建输出按二进制原样传输至构建时指定的 Solaris 安装目录，
   保留 `core.py`、`helper.py`、许可、说明、配置、manifest、全部脚本和空 `runs/`。
   更换安装位置必须重新构建、重新验收。
2. 限制目录与证据访问权限。Pinnacle 运行账户须能读取脚本和依赖、执行 Python、
   写入 `runs/`；建议安装目录及 `runs/` 仅该账户访问（目录权限 `700`）。
3. 不要用文本编辑器改写生成的 `.Script`：末尾含二进制原生校验和，
   不可改变编码、换行或通过文本模式传输。
4. 用户任选一种方式运行 **`Start-CPCleaner.Script`**：
   - **Scripting 窗口**直接选择安装目录中的启动脚本；
   - **HotScriptList** 按机构现行维护流程注册 `HotScriptList.entries` 中的单条条目。
     它是条目片段，不是完整原生列表；保留原列表其他条目及正确校验和，
     不要直接追加到原文件校验和之后。

构建器不会修改全局 HotScriptList。启动脚本不是单文件可执行工具：
**只拷走启动脚本而不安装完整依赖无法运行。**

## 一次启动的行为

1. 采集身份与空闲状态，显示当前 Trial 名和研究用途警告，默认 **No**。
   No 停止，不分析候选、不导入；Yes 后重采快照核对，输入变化则拒绝。
   Check/Clean/Verify 分步入口同样要求此次确认，不因名称符合旧前缀而跳过。
2. 检查当前**整个 Trial**，不是仅当前选中的 Beam/Segment。
   无候选时报告并退出，不再询问清理、不修改、不导入。
3. 有候选时显示数量、射束/分段/叶对、差异及闭合策略，另一次确认默认 **No**。
   超过 12 项时只显示前 12 项及完整报告路径；操作员应先审阅全部报告再决定。
4. 明确 Yes 后重新采集当前/全部 Trial、机器、叶片和空闲状态。
   任何输入变化或未知 getter 均拒绝；原生 guard 通过后只导入目标叶片曲线。
5. 自动读回核验全部 Trial 的受保护序列化字段和预期几何，并确认旧剂量失效。
   仅归一化已定位的 Save 时间副作用：
   `ObjectVersion.WriteTimeStamp` 和
   `BrachyImplantDateAndTime.UTC_ISODateAndTimeString`。

No 不产生导入 claim。入口和各阶段预写安全失败脚本；helper 失败不重放旧导入。
已 claim 未完成时拒绝重新启动清理；保留证据，使用 `03-Verify.Script` 或人工对账，
**不要删除 claim 后重试**。不自动回滚，不假定中断意味着未发生部分修改。

`01-Check.Script`、`02-Clean.Script`、`03-Verify.Script` 保留为分步检查/对账入口。
Verify 应在剂量重算前运行；重算后的合法字段变化可能使严格核验拒绝。

所有结果始终 `exportReady=false`。
**不自动计算剂量、保存计划或向治疗系统导出。**
实际发生修改后必须重新计算最终剂量、重新评价、完成适用的 QA 并重新确认计划；
不得沿用旧剂量、旧评价或原批准状态。

## 性能与核验

同一次 helper 阶段内，按文件实际字节复用解析结果及规范化指纹；
每次访问仍读取文件内容，文件变化不会命中旧结果。阶段结束（包括失败）立即释放缓存，
不同阶段、不同运行及用户确认前后不共享缓存。单入口不再与自身重复比较，
预览分析结果直接用于生成曲线，不再重复运行相同分析。
确认后的新鲜快照、全字段比较、逐叶片原生 guard、导入后核验保持不变。

Solaris Python 2.7.9 上，同一 7 束 / 67 CP 研究快照的只读对比：
Python 预览计算约 28.7 → 1.6 秒，授权检查及 guard 生成约 39.8 → 7.0 秒。
完整规范化报告、曲线字节和原生 guard 字节哈希一致。
这是单个快照的 Python 部分测量，不含弹窗等待、原生导出/执行及磁盘写入，
不是端到端时间保证或其他规模计划的速度承诺。

## 验证状态与未完成项

- 分步流程的先前研究迭代曾在 Pinnacle 16.2 / Edge 单束单段水模体完成
  No/Yes、原生曲线导入、读回、剂量失效、Verify 和无异常复查。
  这不代表当前独立仓库版本已完成同等原生验收。
- 当前算法含正常动态闭合间隙误报修正；不要使用缺少此判定的早期原型。
- 当前独立版本的单入口流程有 31 项合成测试，已在本机 Python 3 和 Solaris Python 2.7.9 通过，
  包含阶段缓存隔离、文件变化识别、共同闭合参考、移动范围遮挡、
  约束回退、任意 Trial 名确认及确认期间变化拒绝。
  后续版本的测试结果以对应测试命令及 CI 为准。
- X/Y、替代 Jaw、不同叶对数量、多束多段等组合为**合成测试**，不是这些机器的现场验收。
- 前一研究预览版有用户独立运行记录，6 项修改自动读回通过；不是全面机器或临床验收。
- 当前优化版已由用户从独立入口运行，研究警告、清理确认、原生导入及自动核验完成；
  7 束 / 67 CP 的研究 Trial 中，9 项候选涉及两个 CP，其中 7 项采用共同闭合参考，
  2 项因同叶对有多个开口 CP 而按原中点闭合。证据的独立只读复核通过，清理后候选为 0。
  此记录不代表任意名称、每个入口/拒绝分支或全部机器配置都已完成现场验收。
- **尚未完成全面机器交付性、清理后最终剂量等价性、复杂计划和临床放行验收。**
- 全字段序列化比较不等于所有 XDR/附属剂量二进制的数值等价验证。
